产研协作流程

人做决策，AI 做工具

一条需求从提出到上线，是产品、设计、研发、测试这些人之间的协作；AI 只是每个人手里的效率工具——写草稿、写代码、写用例、做 diff 审查建议。评审、决策、发布、担责，始终是人。

01 · 角色与职责

产研测的角色与职责

六个角色，都是人。每人有明确的职责与不可替代的部分，AI 只在「工具辅助」一列提供帮助。

角色职责AI 工具辅助人负责（不可替代）
产品 PM需求洞察、PRD、需求评审、优先级、验收写 PRD 草稿、竞品分析、用户故事整理需求取舍、评审拍板
设计交互 / 视觉设计出初稿、找灵感、切图设计定稿、设计评审
技术负责人技术方案、架构、代码评审技术调研、diff 审查建议架构决策、评审结论
开发编码、自测、联调、修复写代码、单测、debug、解释代码代码质量、自测、联调
测试 QA测试用例、功能测试、回归、发布验收生成用例草稿、测试数据、报告整理用例设计、缺陷判定、验收
发布 / 运维发布、监控、回滚、告警日志分析、告警摘要发布决策、回滚拍板
关键：AI 帮助「备料」，不替代「拍板」。 每个角色的 AI 工具只做提升效率的粗活，评审结论、需求取舍、发布决策这些不可逆的事，都由人对结果负责。
02 · 需求开发

需求开发：从 PRD 到上线

一条新需求，经过四道评审门（需求 / 设计 / 技术 / 发布），由不同角色接力完成。

03 · Bug 修复

Bug 修复：分级、定位、回归

bug 先由 PM 定级定优先级，高优先级走「定位根因 → 修复 → 评审 → 回归」闭环，严重 bug 最后做 RCA 复盘。

04 · Git 协作

Git 协作：一个需求一个分支，一次评审一次合入

分支按需求 / 修复开，合入前必须过 CI 机器门禁和人工代码评审。

05 · AI 的位置

AI 只是工具，不是流程里的角色

AI 不占据流程的任何一个阶段，也不充当任何一个角色。它像 IDE、像测试框架一样，是每个角色手里的工具。

AI 帮人做的（效率）

  • 写 PRD / 设计稿 / 测试用例的草稿
  • 写代码、写单测、debug
  • 做 diff 审查建议、技术调研
  • 整理信息、日志分析、报告

AI 不碰的（决策与担责）

  • 定需求优先级、定架构方向
  • 在评审会上拍板
  • 决定是否发布、是否回滚
  • 对线上结果负责
一句话： 流程是产研测的人跑出来的，AI 只是让每个人跑得更快。它产出的是「草稿」，人产出的是「决策」。
